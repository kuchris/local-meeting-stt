## What's new

- The desktop app is rewritten in Rust ([Tauri 2](https://tauri.app/)). Its window uses the WebView2 runtime built into Windows instead of a bundled Chromium, so the executable is about 4.5 MB (the v0.3.0 Electron app was about 327 MB unpacked).
- New interface: **Live**, **Record**, **Recordings** and **Settings** in one quiet layout, with light, dark and system themes. The interface language is now chosen in Settings.
- Live captions are merged in the app's Rust core and added to the page in place, so a long meeting no longer redraws the whole window for every caption. The merging rules are unchanged and are tested against the previous version's own code.
- Audio devices are read directly from Windows in milliseconds instead of starting Python for each refresh.
- Drop an audio file anywhere in the window to transcribe it. A recording's existing transcripts open from **Recordings** in one click.
- The backends, their launch settings and `settings.json` are the same as v0.3.0, so existing settings, models and output folders carry over. The previous Electron app remains on the [`electron` branch](https://github.com/kuchris/local-meeting-stt/tree/electron).

## Download and setup

1. Download **Local.Meeting.STT.portable.v0.4.0.zip** and extract the entire folder to a writable location.
2. Install [uv](https://docs.astral.sh/uv/getting-started/installation/) and make it available on PATH, then launch **Local Meeting STT.exe**. The window needs the Microsoft Edge WebView2 Runtime, which Windows 11 includes; on Windows 10 without it, install the [Evergreen runtime](https://developer.microsoft.com/microsoft-edge/webview2/).
3. In **Settings**, download the model and CPU/CUDA runtime you want to use. First use also downloads Python dependencies.

This Windows x64 package includes Vulkan, Vulkan loopback, and OpenVINO runtimes. Model weights, Python environments, caches, and recordings are excluded. OpenVINO encoder files must be prepared separately. Hardware and driver requirements depend on the selected backend.

Recognition remains local. The supplied recognition workflows use Japanese; switching the interface language does not change the recognition language. Qwen is for file transcription, not live captions.

Extract this version into a new folder; copy existing models and recordings as needed. Keep the backend folders beside the executable. The app is unsigned, so Windows may show an unknown-publisher prompt.

## Verification

The extracted package was checked for startup outside the repository and from another working directory, version 0.4.0, English defaults, detection of the bundled runtimes, and audio device listing. The packaged executable completed a whisper.cpp CUDA transcription of a synthesized Japanese sample using locally installed model weights. In development builds, stopping a running transcription ended its process tree, and closing the window during a job waited for cleanup before exiting. The caption tests replay a fixture produced by the v0.3.0 caption code.

This is not a clean-machine installation test or a real meeting capture test: live captions and audio recording were not run against real meeting audio.

Use **SHA256SUMS.txt** to check the ZIP with PowerShell `Get-FileHash -Algorithm SHA256`.
